# Market Positioning

## Target customer

The initial target is a developer/team that:

- built an application on Supabase;
- likes the Supabase developer experience;
- is preparing for or already operating in production;
- wants more predictable or lower production database/platform cost;
- wants a migration path that minimizes application changes;
- may benefit from MaluDB-specific memory/database capabilities.

## Positioning statement

MaluDB Platform is a Supabase-compatible production alternative powered by MaluDB.

Compatibility gets a customer in the door. Price/performance and MaluDB capabilities provide the reason to stay.

## Messaging principles

Prefer:

- "Supabase-compatible for supported features"
- "Designed for low-friction migration"
- "Production-oriented"
- "Predictable resource-based plans"
- "Powered by MaluDB"

Avoid until proven:

- "100% Supabase compatible"
- "drop-in replacement for every Supabase feature"
- hard savings claims without measured comparable workloads
- performance claims without repeatable benchmarks

## Competitive moat

The defensible portion of the platform should become:

1. migration tooling;
2. compatibility validation;
3. operational economics on shared MaluDB nodes;
4. resource governance;
5. MaluDB-specific memory/database features.
